# Video Sitemap DA App — Complete Implementation Analysis

## What Was Done and Why

### Background

Previously `video-sitemap.xml` was generated by a **GitHub Actions workflow** (`.github/workflows/video-sitemap.yaml`) that ran `tools/generate-video-sitemap.js` and committed the resulting XML file directly to the repository. Every sitemap refresh created a git commit — a noisy, code-coupled approach.

**Goal:** Replace this with a **Document Authoring (DA) App** that:
1. Generates the XML in the browser
2. Writes it to DA via the DA Admin API
3. Publishes it to AEM Edge Delivery via the AEM Helix Admin API
4. Makes **zero git commits**

## How the App Works (Final Correct Flow)

```
DA App (da.live iframe)
       │
       ▼
1. fetchVideoIndex()
   GET  CORS_PROXY?url=https://main--repo--org.aem.live/video-index.json
   (via daFetch — IMS token injected)
       │
       ▼
2. generateXml()  [client-side, no network]
   Builds Google Video Sitemap XML from filtered rows
       │
       ▼
3. writeSitemapToDa()
   PUT  https://admin.da.live/source/org/repo/video-sitemap.xml
   (via daFetch — DA Admin accepts da.live origin natively, no CORS proxy needed)
       │
       ▼
4. publishSitemapInDa() — Step A: Preview
   POST CORS_PROXY?url=https://admin.hlx.page/preview/org/repo/main/video-sitemap.xml
   (via daFetch — body-less POST, no Content-Type header)
       │
       ▼
5. publishSitemapInDa() — Step B: Live
   POST CORS_PROXY?url=https://admin.hlx.page/live/org/repo/main/video-sitemap.xml
   (via daFetch — body-less POST, no Content-Type header)
       │
       ▼
Result: video-sitemap.xml served at https://main--repo--org.aem.live/video-sitemap.xml
        No git commit. No GitHub Actions. No bot token.
```

## Errors Encountered and How Each Was Fixed

### Error 1 — CORS on video-index.json fetch

**Symptom:** Browser blocked the request to `*.aem.live/video-index.json` with a CORS error.

**Root cause:** The DA app runs inside a `da.live` iframe. `*.aem.live` does not include `da.live` in its CORS `Access-Control-Allow-Origin` header.

**Fix:** Route the request through the same CORS proxy worker used by `publish-requests-inbox/api.js`:
```js
// Wrong (CORS blocked):
const resp = await fetch(`${host}/video-index.json`);

// Correct (proxy + daFetch for IMS auth):
const CORS_PROXY = 'https://da-etc.adobeaem.workers.dev/cors';
const proxiedUrl = `${CORS_PROXY}?url=${encodeURIComponent(indexUrl)}`;
const resp = await daFetch(proxiedUrl);
```

---

### Error 2 — 404 on admin.da.live/publish

**Symptom:**
```
POST https://admin.da.live/publish/kprasad05/aig-eds-migration-poc/video-sitemap.xml
Status: 404 Not Found
```

**Root cause:** `admin.da.live/publish` is for publishing DA **document** content (`.html` pages). It does not handle `.xml` files and returns 404 for them.

**Fix:** Use the **AEM Helix Admin live endpoint** instead — the same endpoint that `publishContent()` in `publish-requests-inbox/api.js` uses:
```js
// Wrong:
POST https://admin.da.live/publish/org/repo/video-sitemap.xml

// Correct:
POST https://admin.hlx.page/live/org/repo/main/video-sitemap.xml
```

---

### Error 3 — 404 on admin.hlx.page/live (before preview)

**Symptom:**
```
POST https://da-etc.adobeaem.workers.dev/cors?url=https://admin.hlx.page/live/.../video-sitemap.xml
Status: 404 Not Found
```

**Root cause:** For DA-sourced files, `admin.hlx.page/live` returns 404 if the file has not been through **preview** first. AEM Edge Delivery requires the two-step flow: `preview` → `live`.

**Fix:** Add a preview step before the live publish:
```js
// Step 1: Preview
POST https://admin.hlx.page/preview/org/repo/main/video-sitemap.xml

// Step 2: Publish to live  
POST https://admin.hlx.page/live/org/repo/main/video-sitemap.xml
```

---

### Error 4 — 415 Unsupported Media Type on preview

**Symptom:**
```
POST https://da-etc.adobeaem.workers.dev/cors?url=https://admin.hlx.page/preview/.../video-sitemap.xml
Status: 415 Unsupported Media Type
```

**Root cause:** We were passing `headers: {}, body: null` to `daFetch`. Passing any `headers` object (even empty) or `body: null` causes `daFetch` to inject a `Content-Type` header. The `admin.hlx.page/preview` endpoint expects a completely **body-less POST** — if it receives a Content-Type it rejects with 415.

**Fix (attempt 1 — still wrong):** We thought `encodeURIComponent` was the issue, but that was a secondary concern. The real fix was matching the **exact pattern** from `publishContent` in `publish-requests-inbox/api.js`:

**What `publishContent` does (the working reference):**
```js
// From api.js — this WORKS:
const publishUrl = `${CORS_PROXY}?url=https://admin.hlx.page/live/${org}/${site}/main${cleanPath}`;
const response = await daFetch(publishUrl, { method: 'POST' });
// Key points:
// 1. URL is NOT encodeURIComponent'd in the ?url= parameter
// 2. Options are ONLY { method: 'POST' } — no headers:{}, no body:null
```

**Our final fix:**
```js
// Wrong (causes 415):
const hlxOpts = { method: 'POST', headers: {}, body: null };
const url = `${CORS_PROXY}?url=${encodeURIComponent(`${base}/preview${path}`)}`;
await daFetch(url, hlxOpts);

// Correct (matches publishContent pattern exactly):
const url = `${CORS_PROXY}?url=${base}/preview${path}`;  // no encodeURIComponent
await daFetch(url, { method: 'POST' });                   // only method, nothing else
```

## Key Patterns from publish-requests-inbox (Reference Implementation)

| Pattern | What it does | Used for |
|---|---|---|
| `CORS_PROXY = 'https://da-etc.adobeaem.workers.dev/cors'` | Proxies external CORS-restricted URLs | Any non-`admin.da.live` external URL |
| `daFetch(url)` | Fetch with IMS token auto-injected | All authenticated API calls |
| `${CORS_PROXY}?url=RAW_URL` (no encodeURIComponent) | Proxy a URL — pass raw, not encoded | `admin.hlx.page` preview/live calls |
| `daFetch(url, { method: 'POST' })` | Body-less POST | `admin.hlx.page` preview and live endpoints |
| `daFetch(adminDaLiveUrl, { method: 'PUT', body: formData })` | Multipart PUT to DA source | Writing files to DA Admin directly (no proxy needed) |
